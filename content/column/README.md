# コラム・お知らせの書き方

このフォルダに Markdown ファイル（`.md`）を1つ置くと、記事が1本公開されます。

## 記事は 3 種類

| type | 一覧での見出し | どんな記事か | 例 |
| --- | --- | --- | --- |
| `report` | できごと・お知らせ | **いちばん大事。** スペースで実際にあったこと | ○○を開催しました／このミシンで○○を縫ってみました／今月の Nippori Share Base／新しいミシンが入りました／イベントのお知らせ |
| `local` | 日暮里のこと | 日暮里繊維街・奥日暮里のこと | 繊維街の歩き方、生地を買ったあとにできること |
| `guide` | ミシンと洋裁の読みもの | 調べものに答える記事 | 家庭用と職業用の違い、ロックミシンとは |

検索向けの読みもの（guide）だけが増えると、「記事を量産しただけのサイト」に見えます。
**Instagram に載せたできごとを、月に 1 本でも report として残す**のがおすすめです。
ひな形は `_template-report.md`（複製して、ファイル名の先頭の `_` を外して使います）。
コードを触る必要はありません。一覧・カテゴリページ・サイトマップ・構造化データ（Article）は自動で更新されます。

## 1. ファイルを作る

ファイル名がそのまま URL になります。半角の英小文字とハイフンで付けてください。

```
content/column/rock-machine-thread-guide.md
→ https://（サイトのURL）/column/rock-machine-thread-guide
```

一度公開したファイル名は変えないでください（URL が変わり、検索結果からのリンクが切れます）。

## 2. 冒頭に記事情報を書く

```markdown
---
title: 記事のタイトル（32文字前後。検索されたい言葉を前のほうに）
description: 検索結果に出る説明文。120文字以内で、記事を読むと何がわかるかを書く。
date: 2026-10-02
category: machine
tags: [ロックミシン, 糸]
cover: shelfLock
cta:
  href: /sewing-machine#lock
  label: 使えるロックミシンを見る
---

ここから本文。
```

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| `title` | ○ | 記事タイトル。ページの h1 になります |
| `description` | ○ | 検索結果・SNS に出る説明文 |
| `date` | ○ | 実際に公開する日（`YYYY-MM-DD`）。未来の日付にすると、その日まで公開されません。**検索のために日付をずらさない** |
| `category` | ○ | 下の一覧から1つ |
| `type` |  | `report` / `local` / `guide`。省略するとカテゴリから決まります（news → report、textile-town → local、ほかは guide） |
| `instagram` |  | 同じ内容の Instagram 投稿の URL。記事の下に「Instagram で見る」ボタンが出ます |
| `updated` |  | 内容を実際に直した日。書くと「更新日」として表示され、構造化データの dateModified にも入ります。直していないのに書き換えない |
| `tags` |  | 関連記事の判定に使います |
| `cover` |  | 記事の写真。`data/images.ts` の名前（例: `spaceMain`, `shelfLock`, `exterior`） |
| `cta` |  | 記事の最後に出すボタン |
| `order` |  | 同じ日付の記事の並び順（小さいほど先） |
| `draft` |  | `true` にすると公開されません |

### カテゴリ

| 値 | 表示名 |
| --- | --- |
| `machine` | ミシン |
| `sewing` | 洋裁 |
| `handmade` | ハンドメイド |
| `textile-town` | 日暮里繊維街 |
| `workshop` | ワークショップ |
| `monozukuri` | ものづくり |
| `event` | イベント |
| `news` | お知らせ |

記事が1本もないカテゴリのページは作られません。記事が 3 本未満のカテゴリ一覧は、検索結果には出ません（記事そのものは出ます）。

## 3. 本文を書く

- 大見出しは `## 見出し`、小見出しは `### 見出し`（`#` 1つは使わない。タイトルが h1 です）
- 大見出しが3つ以上あると、目次が自動で付きます
- サイト内のリンクは `[ミシンのページ](/sewing-machine)` のように `/` から書く
- 表、箇条書き、**太字** が使えます
- 写真は `![写真の下に出る説明文](/photo/名前)` と書きます。名前は `data/images.ts` にある写真の名前（例: `/photo/shelfLock`）

## 4. 書くときの約束

1. **1記事1テーマ**。ひとつの検索意図（読者の知りたいこと）に、最後まで答える
2. **お店の情報は確認できたことだけ**。料金は税込で書く。料金・設備・時間は `data/pricing.ts`、`data/machines.ts`、`data/equipment.ts`、`docs/VERIFIED_FACTS.md` と食い違わないようにする。台数・営業日・駅からの所要時間は書かない
3. **固定ページと同じ内容を繰り返さない**。「日暮里でミシンを使える場所」のような来店目的の言葉は `/sewing-machine` など固定ページの役割。コラムは「知りたい」に答える読みものにして、最後に固定ページへ案内する
4. **キーワードを詰め込まない**。「日暮里」を無理に繰り返さず、人が読んで自然な文章にする
5. 実在しない利用者の声・レビュー・「地域No.1」のような根拠のない表現は書かない
6. 「〜について解説します」「〜を見ていきましょう」「〜をまとめました」のような決まり文句で始めない・締めない。書き出しは、読者が思い当たる場面から
7. 見出しの並びを毎回同じにしない（「とは → メリット → 選び方 → まとめ」の型にはめない）
8. スペース固有のこと（置いている機種名、実際の写真、当日の様子）を 1 つは入れる

次に書く記事の候補は `docs/column-backlog.md` にあります。
